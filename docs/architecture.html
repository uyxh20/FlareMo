System map

One program, the Worker, does everything. It is the only thing that touches your data.

Search and vectors

Two separate searches. Keyword search matches your exact words. Semantic search matches meaning, using vectors.

Task notes and comments in search fork live since version #50, 2026-11-11: the "Tasks" box above keyword results now asks the Worker (GET /api/app/planner/search?q=), which matches live tasks on title, notes or any live comment, shows the words around the match and the comment's date, and opens the task's panel in the cockpit; the ⌘K list opens a task there too. Keyword only: tasks are not in semantic search. No migration. Code: packages/domain/src/planner/task-search.ts, apps/web/src/planner/task-search-results.tsx.

Memory (being removed)

On dev since 2026-11-11, not live yet upstream v0.32.1: upstream FlareMo deleted Memory, and the fork follows with no archive. Migration 0044 drops every memory_* table and memory_fts; the Memory page, /memory/mcp, the nightly dreaming and memory upkeep steps, the memories search index and the agent's memory tools and cards all go. The weekly and period reviews no longer read memories, and the propose step offers goals and tasks only. The agent's own notes (its memory store) are not affected. Until the upgrade reaches live, live still holds 126 memories and everything described elsewhere on this page about them stays true there.

Weekly review fork

Look back chats about the week and writes a summary. Look forward turns goals into a plan. Weekends review this week, weekdays last week. A week runs Monday 00:00 to Monday 00:00 in your own time (Copenhagen), so a note written at 00:30 on Monday counts for the new week. On live the diary agent runs every step in one session per week and reads what it needs; the first figure is what a single model call gets when the agent cannot start.

Choose the week, live since version #44 (2026-11-08): one set of suggested goals, not two. The agent's proposed goals are stacked rows whose wording and objective (pillar) you can change before Add; Add makes the row a goal of the week, shown underneath. The summary's Next Steps no longer pre-fill four goal cards at the bottom; the empty starting slot per objective stays hidden until you fill it or press "+ Add a goal". No migration. Code: apps/web/src/planner/review-proposals.tsx, review-forward.tsx, review-model.ts (plannerShownGoals).

The cascade ladder, live since version #47 (2026-11-08): the review now judges the week against the goal cascade, not the week alone. For each objective the agent sees the year, quarter, month and week goal, each upper goal with "x of n points struck" and the weeks left in the month, quarter and year. The memo gets two bullets per objective before Evidence: Serves (the month goal and its open points) and Moved (Advanced, Maintained, Drifted or Idle), and Pattern and Risk name the goal most behind its time. Rules: "0 of n struck" is a question to check against the diary, never a verdict (struck counts lag); "losing" needs a diary fact; a missed weekly goal or broken tracked target is Drifted, never Maintained. A switch, the Worker var FLAREMO_REVIEW_CASCADE=ladder, turns it on or off in one deploy (FLAREMO_PROD_REVIEW_CASCADE=ladder or flat for the prod script). Tested on dev against the live review (about 21% more cost per replayed week; one live week, 2 to 8 Nov: same open point, richer month and quarter view, no invented facts). The agent also moved from high to medium effort the same day, for the review and for Ask my diary. A dev-only replay cut (FLAREMO_REVIEW_AS_OF, never set on live) hides what was written after a replayed week. No migration. Code: packages/domain/src/planner/review-cascade.ts; details: docs/fork-general-agent.md, "The cascade ladder".

Replies as they are written, and files in the review fork live since version #49 (streaming coach), #50 (memo, files): in Look back (the week's, and the month, quarter and year chats) the coach's reply now shows word by word while the agent writes it. The Worker opens the agent session's live event stream and passes the text on as short NDJSON lines; the page still asks for the finished answer every 4 seconds, and that answer is the one kept, so a broken stream loses nothing. No model cost; one extra long-lived call per reply. Only the coach streams: the opening, scores and goal check are read whole, and the memo is a file. Live since version #50, 2026-11-11: the summary memo streams too. The agent gives the memo as its reply instead of a file, the page shows it from its title line as it is written, and the Worker still reads an older agent's memo.md as a fallback. The answer box also takes up to three files (drop, paste or the paperclip), read at once through the same /chat-files routes as Ask my diary and deleted; their text goes to the coach with the answer, and the review keeps only the names ("📎 run.pdf"). No migration. Code: apps/worker/src/fork/agent-stream.ts, apps/web/src/planner/review-back.tsx; details: docs/fork-general-agent.md, "Replies as they are written", and docs/fork-task-attachments.md, "Files in the review".

More task text in the review fork live since version #50, 2026-11-11: each task's notes and comments now share 1,500 characters (was 600), notes taking at most 600. Comments written in the reviewed week go in first, then older ones newest first, still shown oldest first with "(N older comments left out)" when some do not fit; before, a long-running task lost its newest updates. Code: plannerReadTaskDetails in review-context.ts.

Retired: the weekly memo agent of 17 October. It ran look back alone on a Managed Agent; the general diary agent took over every job in version #33. Its FLAREMO_REVIEW_MEMO_* vars are still on live and do nothing. Since version #42 each saved look back and look forward is also written to the flywheel log (sizes and counts only), and Look back's side panel carries the flywheel card.

Talk: the review by voice fork on dev since 2026-11-11: a Talk button beside Send in Look back's answer box turns it into a voice bar. The coach's newest message is read out, the microphone listens, through any pause, until you tap the Send bubble (since 2026-11-12; pauses no longer end your turn), and what you said is sent as a typed answer, so the review's model stays the brain and nothing about the review changes. Hearing and speaking run on Workers AI through the existing AI binding: Deepgram nova-3 listens and aura-2 speaks; FLAREMO_REVIEW_VOICE=basic uses Whisper and MeloTTS instead (also the automatic fallback when a natural call fails), and off hides the button. Works on the free plan (checked on dev). Nothing is stored, no migration. Routes: /api/app/planner/voice, /voice/transcribe, /voice/speak. Code: apps/worker/src/fork/review-voice.ts, apps/web/src/planner/review-voice.ts; details: docs/fork-review-voice.md.

Month, quarter and year reviews fork

The weekly review's superset. A period closes on the Sunday of its last week (a week belongs to the month of its Thursday). That Sunday stays one sitting: Look back, then the period review in the middle, then Look forward against the new goals. Five steps per level, the same shape as the weekly: raw rows on the right, your words and a reader on the left, a memo you edit, Save. The model reads, checks, counts and quotes; goals, verdicts and marks are yours. Design: docs/planning-cockpit-period-review.md. Live since 2026-10-17 (version 31, migration 9013 added the period review tables).

Diary agent fork

One Claude agent does every thinking job. It can read everything and change nothing on its own: each write is a card you accept, and every accepted change can be undone. Live since version #33 (2026-10-20); write access by proposal since #36.

Four more Ask buttons fork live since version #50, 2026-11-11: beside Find to-dos, Ask my diary offers Mark what I already did, Replan my week, Tidy my backlog and What did my health log miss, each answering with the editable change card. New Ask-only read tools find_done_tasks, find_replan_tasks, find_stale_backlog, compare_health; a Done row shows the entry it relied on. At most four buttons show; Replan and Tidy carry counts from GET /api/planner/agent/ask/starters (no model) and hide at zero. Proposals and learning log rows record the button (change.starter). Tested with the real agent on dev; two fixes before shipping: the health check proposes an unlogged run even when the day already has a gym row, and Mark done matches a little more loosely. No migration. Code: packages/domain/src/planner/ask-starters.ts, apps/web/src/planner/ask-starters.tsx; details: docs/fork-general-agent.md, "The starter buttons".

Diary to-dos into tasks fork live since version #50, 2026-11-11: Ask my diary's empty chat offers Find to-dos in my diary. A new read tool, find_todos, lists the lines of the last 14 days' entries that read like a to-do (an open "- [ ]" box, "need to", "don't forget", "il faut"…, fixed word rules, no model), each marked when a board task already covers it or it was offered before. The agent keeps the real ones and proposes each as a new-task card that shows the entry and its words; the server checks the words are in that entry and never offers the same to-do twice. On a card, Accept N, skip M now settles the unticked rows as Skipped. The learning log gains proposal.skipped, and proposal.accepted_edited notes a diary to-do and how many title characters you rewrote (never the words); the scorecard gains "left unticked", "diary to-dos taken" and "edited first". Also fixed: an "add health row" card no longer counts a session twice when the diary reader logged it in the meantime (a #wimhof tag accepted on the same card); it fixes the reader's row instead. No migration. Code: packages/domain/src/planner/diary-todos.ts, agent-skip.ts; details: docs/fork-general-agent.md, "To-dos from the diary".

Link summaries, live since version #45 (2026-11-08): drop a link (any web page, a YouTube video, a PDF) into Ask my diary, use Summarize link in an entry's ⋯ menu, or tap the ✦ button in the composer's toolbar (greyed out until the text holds a link; since version #46). The agent's new read_link tool asks the Worker to fetch it, because the agent's sandbox still has no web. It only opens links you gave it, in the chat or in the named entry. It reads a page's main text, a YouTube transcript (or only the title and description when YouTube gives none), or a PDF through Workers AI. The agent then proposes a summary card that says how much it read. Accept saves an entry with source link-summary, tagged #link and linked to your entry, and your thoughts go on it as comments. The review, memory quotes and dreaming label or skip it as "not the owner's words". No migration. About $0.17 a summary (measured on dev). Code: apps/worker/src/fork/link-read.ts, apps/web/src/fork/summarize-link.tsx; details: docs/fork-link-summaries.md.

Cockpit and task history fork

One board on top of FlareMo's tasks, and a history log that outlives the tasks themselves.

A task can also carry files, and its Notes have an Ask agent button that opens the task's own agent chat. Six cockpit tools are open to outside AI agents over /mcp (see Login, apps and MCP).

Sidebar reminders. The red "N overdue" line and the "still open today" box above the time horizon count cockpit tasks that are open (not done, not dropped) and due before or on today, from any month, and both open the cockpit. The count is one read-only query (GET /api/app/planner/overdue, packages/domain/src/planner/overdue.ts) that never writes to D1. Upstream's version counted only this month's first 100 tasks and opened the hidden Projects page; the one-line swap is in flaremo-explorer.tsx.

Files on tasks and in the chat fork

Drop an email, a PDF, a picture or a web page on a task. The file is stored, read once, and its text comes back as a comment you accept. Live since version #37 (2026-11-02); short files whole and long ones summarised since #40. Live since version #43 (2026-11-05): audio, video and iPhone photos too, and files in Ask my diary (second figure).

Goals fork

Five levels, each split across four pillars. Tasks point at the goal they serve.

Morning page fork

The first time the diary opens each day it shows a full page: the date, one idea line written from your own life, what is due, and the week's goals. "Start the day" puts it away until tomorrow. Built on branch claude/morning-card, not live yet.

Flywheel fork

What you keep, edit and undo becomes a weekly scorecard of the agent against your own work, and that scorecard feeds small changes to the agent's standing instructions. Nothing changes the agent until you press a button. Live since version #42 (2026-11-04).

Health tracker fork

Live since 2026-10-13 (version 17). Nothing new to type: every saved entry is read for training, breathwork and nights out, and the results become rows. No AI; fixed word rules.

Nightly jobs

One housekeeping pass at 03:17 UTC, in this order. One failing step doesn't stop the rest. A second timer fires on Sundays, twice an hour apart: the Copenhagen-noon run does the review prep, the other saves the weekly backup, your full personal export (diary, memories, tasks and every fork table: goals, reviews, task history, agent and health), to R2 as backups/weekly/<date>.json. Copies are kept for good; nothing deletes them (apps/worker/src/fork/weekly-backup.ts).
